# 上线准备交付：下一步只读预检

本轮依据用户“做好准备、继续”的授权完成本地维护入口与验证。**未 push、未上传、未执行 sudo、未安装或改动 Babel 服务。** 实际生产预检、恢复演练和上线审批仍待用户完成。

## 已交付

- `deploy/native/inspect_babel.py`：Genesis 普通用户入口，一条命令完成临时检查脚本复制、远端 sudo 只读预检及正常退出清理。脚本使用唯一文件名，根进程拒绝软链接/特殊文件与异常大小，校验读入内存的完整 SHA 后执行同一份字节，不在校验后重读可变文件。
- `release_inspect.py`：自包含、Babel/root 限定，只读取服务、运行配置和数据库概要。SQL 会话强制只读，密码不出现在命令参数、报告或错误信息中；查询失败明确标记。
- `release_schema.py` / `release_schema_core.py` / `release_schema_host.py` / `release_schema_data.py`：管理员 `rehearse → stage → activate/abort` 流程，复用现有 systemd 执行器、互斥锁、状态记录与中断恢复。普通 Agent RPC 仍只允许 deploy/rollback/status。
- `schema_policy.json`：固定审阅过的 235–237 SQL、原始文件哈希及迁移记账哈希；拒绝额外迁移、历史文件改写或不同候选内容。恢复演练绑定数据库身份、原记账、策略哈希和 24 小时时限。
- Installer 自动处理缺失的 `/usr/local/libexec`，交付新的维护模块、root-only 备份目录及 Nginx 19823 回环维护响应；不增加常驻进程或数据库 sudoers 权限。
- 构建器在导出的 backend 目录记录实际 Go 工具链，不再把外层 launcher 当成编译器版本。

## 恢复保护

1. 候选接触数据库前失败，不回灌数据库，不为无关旧 Nginx 连接而强制重启健康旧 App。
2. 候选启动前保存一致的 DB、已审阅缓存和共享文件；保存必要凭据早于停 App，避免中断后无法连接恢复。
3. 迁移后仍保持维护门控和暂停 worker，停在 `schema_ready` 等人工验收。此时可取消并恢复旧 schema、缓存、共享数据和旧 App。
4. 开放新服务前写入不可回灌边界；旧库恢复后重新启用旧服务前也写入相同性质的边界。中断重试只继续开放对应服务，不会重复回灌数据库丢掉新写入。
5. 不对生产 DROP DATABASE、不 FLUSHDB/FLUSHALL、不清除其他服务键；备份留在服务器 root-only 目录。未完成批任务、其他 DB 连接、环境/路由漂移或恢复校验失败都会阻止继续。
